# 跨章事实与实体连续性

起草、续写、事实修订和连贯性审稿时读取。摘要用于定位，不能代替实体的具体事实与正文证据。校验脚本只能检查数据契约，语义上的冲突仍须逐项比对。

## 先确定“同一个谁或什么”

对本章将使用、以及新出现且可能影响后文的人物、地点、物品、能力或规则，保留稳定的实体标识。叙述名称、简称、别称可以变化，但必须指向已核实的同一实体；不要为了文辞变化替换专名、物品类别、等级、材质或建筑类型。

记录影响辨认或推理的属性，不为所有装饰性细节建档。优先覆盖身份、形制、来源、数量、品质、持有者、位置、能力条件与限制，以及人物获知信息的事件。正文一旦用某属性支持交易、战斗、空间行动等因果，该属性就不能只留在粗略摘要里。

写前在章节意图卡中列出本章相关实体的“既定身份/属性、当前状态、来源、允许发生的变化、仍不确定的事项”。检索没有结果表示未知，不表示可以重新设定；按实体名、已知别称、获得或出现事件回查来源章节的相关段落。无明确依赖时不加载全书。

## 事实记录契约

沿用现有 `canon.json` 与章节 `facts.json`，不另建一份竞争的正史。基本字段仍是 `subject`、`predicate`、`value`、`source_chapter`、`status` 和 `reader_visibility`。对涉及连续性的新增事实，使用以下可选元数据（helper 会原样保存，语义由审稿核验）：

| 字段 | 作用 |
|---|---|
| `entity_id` | 稳定实体标识，跨章复用；不同于事实本身的 `id` |
| `source_anchor` | 来源章中可搜索的短原文或明确段落位置 |
| `kind` | `identity`、`attribute`、`state`、`event`、`knowledge` 等，区分属性、时点状态与事件 |
| `valid_from` | 状态生效的故事时间或事件锚点，不能仅靠章节顺序判断倒叙 |
| `supersedes` | 正常状态变化承接的旧事实 ID；旧记录保留，不自动抹除 |
| `change_reason` | 状态变化在正文中的事件依据 |

例如，一件证物转交给另一人物，应复用证物的 `entity_id`，新增持有状态事实，引用旧状态 ID 和交接事件。不能覆盖最初取得证物的事件，或把后来的持有者当成从一开始就持有。`reader_visibility` 只表示读者可见性；谁听说、目睹、误信了什么，需要另记以该人物为主体、带来源的 `knowledge` 事实。

旧项目不必迁移整个账本；按本章涉及的实体补充索引与证据，不改变旧事实含义。相同信息不必每章重复新增事实；核对无变化即可。首次建立实体标识时要对齐既有主语和来源，避免给同一物件多次建档。

## 写后双向核对

1. **正文 → 正史：** 从实际草稿提取对身份、属性、状态、规则和知识的断言，与已接受事实逐项比较；不要只检查准备写入的 `facts.json`，否则漏记的漂移不会被发现。
2. **事实增量 → 正文：** 每条新增记录必须在本章有依据；意图卡、大纲和模型推断不能冒充已发生事实。修订后的摘要、伏笔与事实必须对应同一版正文。
3. 遇到差异先分类：有依据的别称、叙述粒度变化、人物误认或谎言、有事件支撑的状态变化、真正矛盾。不同措辞不自动判错，相同实体也并非永远不能变化。
4. 无依据的草稿漂移直接修回既定事实；不要补造过去发生过的加工、升级、改建、交接或告知事件。作者授权的正常情节发展可以在本章写出变化过程并登记新状态。
5. 若正文与已确认正史互相矛盾，或必须改动已接受故事才能成立，报告双方来源和影响，按已有授权处理；需要作者决定时保留 `needs_author`，不能自行选一个版本。

新事实 ID 只能避免键重复，不能证明语义上是新事实；提交脚本的同 ID 覆盖保护也无法发现换了 ID 的矛盾。审稿必须检查同一实体、同一属性和同一故事时点。
